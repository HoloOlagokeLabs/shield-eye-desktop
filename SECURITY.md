# Security Policy

## Supported Versions

| Version | Supported |
| ------- | --------- |
| 1.1.x   | ✅        |
| 1.0.x   | ❌        |

Only the latest stable release receives security updates.

## Reporting a Vulnerability

Please do not open a public GitHub issue for security vulnerabilities.

Report security concerns privately and include:

* A description of the issue
* Steps to reproduce
* Affected version(s)
* Potential impact

Contact:

[report@holoolagoke.com](mailto:report@holoolagoke.com)

An initial response is typically provided within 48 hours.

## Scope

Examples of issues that should be reported:

* Database encryption weaknesses
* SQLCipher configuration issues
* PRAGMA key handling vulnerabilities
* Authentication or access-control bypasses
* Update verification bypasses
* Hash verification weaknesses
* Sensitive data exposure
* Log tampering vulnerabilities
* Secure storage weaknesses

## Out of Scope

The following are generally not considered security vulnerabilities:

* UI bugs
* Cosmetic issues
* Performance problems
* Feature requests
* Missing functionality
* Issues requiring physical access to the device without a security impact

## Disclosure Process

After a report is received:

1. The issue will be reviewed and validated.
2. A fix will be developed and tested.
3. A patched release will be published.
4. Public disclosure may occur after a fix is available.
